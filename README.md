# 智能设备健康管理平台大屏

基于 Vue 3、Vite、ECharts 和 lucide-vue-next 实现的静态数字化大屏原型。

## 本地运行

```bash
npm install
npm run dev
```

## 构建

```bash
npm run build
```

## 说明

- 页面入口：`src/App.vue`
- 图表封装：`src/components/EChart.vue`
- 全局样式：`src/style.css`
- 首页使用真实健康接口数据，设备监控整合两套后端，其他页面按原有接入方式运行。

## 健康状态接入（第一步）

首页请求 5158 的 `GET /api/health`、`GET /api/health/detail`、`GET /api/health/table-maintenance`，同时复用 18080 的 `GET /monitor/devices`。默认每 15 秒刷新，可暂停或手动刷新，离开首页即停止轮询并取消未完成请求。各来源独立处理，超时为 10 秒。健康详情返回 HTTP 503 时仍展示 JSON 检查结果；请求失败保留上次数据并明确提示。

健康接口默认地址为 `http://localhost:5158`，可复制 `.env.example` 为 `.env.local` 并设置 `VITE_API_BASE_URL`，修改后重启开发服务。本地开发通过 `/_health-api` 同源代理连接后端，代理仅匹配上述三个健康接口，不转发其他旧接口或新接口。生产构建直接使用配置的后端地址；远程部署时，`localhost` 指浏览器所在电脑，需要配置实际后端地址，并由后端允许前端来源的 CORS 请求；HTTPS 前端应配置 HTTPS 后端或同源反向代理。

`src/services/health.js` 使用独立请求通道，不携带 18080 服务的登录令牌。首页的新设备列表通过现有 `api.getMonitorDevices` 使用 18080 的登录令牌；没有新增监听会话或音频连接。`http://192.168.31.158:18080` 的地址、登录、鉴权和其他页面业务接口保持不变，设备方法仅增加可选取消信号。其他旧接口继续由 `VITE_LEGACY_API_DISABLED` 控制，默认停用。

首页展示心跳、检查明细、数据库及点位状态、模块在线状态、历史/聚合表分区、缓存、配置文件和表维护记录。首页不使用静态预览数据；系统健康与模块在线状态分别统计。

首页主视图采用图表布局：检查通过率仪表盘、模块在线环图与可点击状态矩阵、检查分类条形图、分区覆盖热力图、缓存环图、维护前后分区柱状图及数据管道示意。完整表格保留在底部“完整诊断明细”，展开时才加载。不生成模拟趋势，零缓存显示空环，并适配亮暗主题和减少动态效果设置。

设备区域整合 `runtimeModules.statuses[]`（5158 模块）与 `/monitor/devices`（18080 设备），总览卡片按两边已获取记录相加，环图与状态矩阵支持全部/5158/18080 筛选。旧模块使用 `isOnline`，新设备使用 `online`，字段缺失计为未知；设备下的网关、通道只展示连接情况，不重复计数。使用来源、协议和字符串 ID 区分记录，未建立跨系统映射前不跨来源去重。每个来源显示更新时间和失败/过期状态，未返回的数据不冒充零设备。健康检查、分区、缓存、点位与队列仍只描述 5158。

## 设备监控接入（第二步）

设备监控按来源整合 5158 采集模块和 18080 监控设备，可筛选来源和切换设备。18080 继续调用原有 `GET /monitor/devices`，保留网关、通道字段及原鉴权，仅进入页面或手动刷新时获取，不创建监听会话；声纹实时波形仍使用原有频谱分析功能。

5158 使用独立的 `src/services/telemetry.js`，接入以下四个只读接口，不携带 18080 令牌：

- `GET /api/configuration/modules`：模块目录每 15 秒刷新。
- `GET /api/configuration/modules/{moduleId}/points?includeLatest=false`：切换模块时获取点位和 `pointId`。
- `GET /api/realtime/latest`：选中 5158 模块时每 2 秒刷新，可暂停。按模块、通道、点位编码匹配元数据，每个点位保留最近 300 个实际采样时间点，重复时间戳不追加，零值正常显示，超过 15 秒的采样间隔断线显示。折线只积累本次页面访问的数据，不补造历史。
- `GET /api/telemetry/history?pointId=...&start=...&end=...&limit=...`：使用本地时间和 `pointId` 查询原始数据表格。进入历史模式或在历史模式切换点位时，自动查询当前时间之前 10 分钟，默认最多 5000 条；也可手动调整时间范围查询。查询上限为 1–100000，达到上限时提示可能截断。

两套接口分别显示加载错误，不因一侧失败清空另一侧数据。切换点位会清除旧历史，过期请求不能覆盖新选择，离开页面停止轮询并取消请求。

历史查询结果仅用表格展示，包含采集时间、原始精度数值、单位和原始质量值；默认最新优先，支持时间排序与每页 20/50/100 条分页，分页不额外请求后端。实时数据继续使用折线图。

开发环境新增 `/_telemetry-api` 同源代理，仅匹配上述四个接口；健康代理和 18080 请求地址不变。生产环境直接使用 `VITE_API_BASE_URL`，与健康接口相同，需要配置实际后端地址及 CORS/HTTPS。其他旧接口仍默认禁用，不影响其他页面现有接入。

## 告警管理接入（第三步）

告警管理包含“双源告警总览”“5158 采集报警”“18080 设备告警”。总览按时间合并两侧已获取记录，来源和字符串 ID 独立保留；5158 的限量查询结果与 18080 当前分页不能作为全量告警总数。点击详情进入对应来源，筛选条件及更新时间分别展示。

5158 通过独立 `src/services/alarms.js` 调用 `GET /api/analysis/alarms`，支持可选 `pointId`、`isActive`、`start`、`end` 和 `limit`（默认 200，范围 1–1000），不发送旧的模块/通道组合参数。模块与点位选择复用已迁移的只读元数据服务。默认不限定时段或状态，支持表格分页、阈值/报警值/恢复值详情；达到上限时提示查询可能截断。`GET /api/analysis/status` 展示独立的 Worker 状态，不用内存分析状态替代报警事件。进入页面自动查询，可手动刷新，不新增后台轮询或写操作。

开发环境仅为上述两个分析接口增加 `/_alarm-api` 代理；生产直接使用 `VITE_API_BASE_URL`，同样需要配置 CORS/HTTPS。5158 不携带 18080 令牌，失败会明确提示并保留原成功查询快照，不将错误当成空列表。18080 的 `/alarm/page`、录音、样本类别和每日统计继续使用原请求方法、参数及鉴权。

当前联调限制（2026-08-28）：本地 5158 的报警事件接口返回 HTTP 500（空响应体），分析状态接口正常。前端按既有 `events` 包装或直接数组解析，未知结构报错；事件列表成功渲染使用测试数据验证，真实成功响应结构和状态枚举仍待后端恢复或提供示例确认。页面不包含测试报警或原静态预览告警。
