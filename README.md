# 智能设备健康管理平台大屏

基于 Vue 3、Vite、ECharts 和 lucide-vue-next 实现的静态数字化大屏原型。

## 本地运行

开发和构建均使用真实后端数据，需要后端服务可用并使用真实账号登录。

```bash
npm install
npm run dev
```

## 构建

```bash
npm run build
```

## 登录 API 配置

复制 `.env.example` 为 `.env.local`，通过 `VITE_LOGIN_API_URL` 指定完整登录接口地址（含路径），例如：

```dotenv
VITE_LOGIN_API_URL=http://66.66.66.4:18080/auth/login
```

也可使用同源路径，例如 `VITE_LOGIN_API_URL=/auth/login`，由部署服务器转发请求。留空时沿用 `VITE_NEW_API_BASE_URL` 对应服务的 `/auth/login`；开发环境未配置该服务地址时使用 `VITE_DEV_NEW_API_BASE_URL`，生产环境未配置时跟随页面主机并使用 18080 端口。登录仍以 POST 表单提交账号和密码，不携带已有登录令牌。

开发环境修改 `.env` 后须重启 Vite。生产环境可通过 `.env.production` 设置部署地址，修改后须重新构建并部署；直接修改已部署静态文件旁的 `.env` 不会生效。不要将账号、密码或令牌放入 `VITE_*` 配置。

## 数据展示大屏

登录后通过侧栏“数据展示大屏”进入 `/#/data-screen`。大屏沿用亮暗主题，自动隐藏侧栏并压缩顶部导航，以九区网格展示采集模块、全部点位实时值、所选点位曲线、系统检查与管道、数据表分区与缓存、硬限值和趋势报警、原始历史数据、每日限值趋势及趋势洞察。仅使用 5158 采集服务，不请求声纹设备、录音或频谱服务，也不发送其登录令牌。

实时采样每 2 秒刷新，总览、点位元数据及分析每 60 秒刷新；支持暂停、手动刷新、点位搜索与切换，并复用顶部主题与全屏按钮。曲线只积累本次访问的真实采样；历史默认查询最近 10 分钟（最多 5000 条），趋势与洞察查询最近 30 天，每类报警最多 1000 条，达到上限时提示可能截断。面板内部滚动展示全部已获取记录，点击模块、检查、数据表、报警及详情按钮查看完整字段。各来源显示成功更新时间，失败保留旧数据并提示；离开页面停止定时器并取消请求。大屏优先适配 1366×768 及以上桌面，较小高度采用网格内部滚动。

运行环境须满足 Vite 的 Node 要求（例如 Node 22.12+ 的 22 系列）。Windows 安装使用 `npm ci --include=optional`，确保 Rolldown 原生依赖完整。

## 健康状态接入（第一步）

首页请求采集服务的 `GET /api/health`、`GET /api/health/detail`、`GET /api/health/table-maintenance`，同时复用声纹服务的 `GET /monitor/devices`。默认每 15 秒刷新，可暂停或手动刷新，离开首页即停止轮询并取消未完成请求。各业务独立处理，超时为 10 秒。健康详情返回 HTTP 503 时仍展示 JSON 检查结果；请求失败保留上次数据并明确提示。

本地开发通过 `/_health-api` 同源代理连接 `http://66.66.66.4:5158`，代理仅匹配上述三个健康接口，不转发其他旧接口或 18080 接口。生产环境未配置 `VITE_API_BASE_URL` 时同样请求 `/_health-api`，由 Nginx 转发到 `66.66.66.4:5158`，浏览器不再跨域访问后端。需要直连其他服务器时可复制 `.env.example` 为 `.env.local` 并设置 `VITE_API_BASE_URL`。

`src/services/health.js` 使用独立请求通道，不携带 18080 服务的登录令牌。首页的新设备列表通过现有 `api.getMonitorDevices` 使用 18080 的登录令牌；没有新增监听会话或音频连接。未配置 `VITE_NEW_API_BASE_URL` 时，开发环境通过 Vite、生产环境通过 Nginx 同源代理连接 `66.66.66.4:18080`，避免浏览器跨域请求；监听 WebSocket 和录音地址也使用同一入口。登录、鉴权和其他页面业务接口保持不变。其他旧接口继续由 `VITE_LEGACY_API_DISABLED` 控制，默认停用。

首页展示心跳、检查明细、数据库及点位状态、模块在线状态、历史/聚合表分区、缓存、配置文件和表维护记录。首页不使用静态预览数据；系统健康与模块在线状态分别统计。

首页主视图采用图表布局：检查通过率仪表盘、模块在线环图与可点击状态矩阵、检查分类条形图、分区覆盖热力图、缓存环图、维护前后分区柱状图及数据管道示意。完整表格保留在底部“完整诊断明细”，展开时才加载。不生成模拟趋势，零缓存显示空环，并适配亮暗主题和减少动态效果设置。

设备区域整合 `runtimeModules.statuses[]`（采集模块）与 `/monitor/devices`（声纹设备），总览卡片按两边已获取记录相加，环图与状态矩阵支持全部/采集模块/声纹设备筛选。采集模块使用 `isOnline`，声纹设备使用 `online`，字段缺失计为未知；设备下的网关、通道只展示连接情况，不重复计数。使用来源、协议和字符串 ID 区分记录，未建立跨系统映射前不跨来源去重。每个来源显示更新时间和失败/过期状态，未返回的数据不冒充零设备。健康检查、分区、缓存、点位与队列仍只描述采集服务。

## 设备监控接入（第二步）

设备监控按业务整合采集模块和声纹设备，可筛选来源和切换设备。声纹服务继续调用原有 `GET /monitor/devices`，保留网关、通道字段及原鉴权，仅进入页面或手动刷新时获取，不创建监听会话；声纹实时波形仍使用原有频谱分析功能。

采集服务使用独立的 `src/services/telemetry.js`，接入以下四个只读接口，不携带声纹服务令牌：

- `GET /api/configuration/modules`：模块目录每 15 秒刷新。
- `GET /api/configuration/modules/{moduleId}/points?includeLatest=false`：切换模块时获取点位和 `pointId`。
- `GET /api/realtime/latest`：选中采集模块时每 2 秒刷新，可暂停。按模块、通道、点位编码匹配元数据，每个点位保留最近 300 个实际采样时间点，重复时间戳不追加，零值正常显示，超过 15 秒的采样间隔断线显示。折线只积累本次页面访问的数据，不补造历史。
- `GET /api/telemetry/history?pointId=...&start=...&end=...&limit=...`：使用本地时间和 `pointId` 查询原始数据表格。进入历史模式或在历史模式切换点位时，自动查询当前时间之前 10 分钟，默认最多 5000 条；也可手动调整时间范围查询。查询上限为 1–100000，达到上限时提示可能截断。

两套接口分别显示加载错误，不因一侧失败清空另一侧数据。切换点位会清除旧历史，过期请求不能覆盖新选择，离开页面停止轮询并取消请求。

历史查询结果仅用表格展示，包含采集时间、原始精度数值、单位和原始质量值；默认最新优先，支持时间排序与每页 20/50/100 条分页，分页不额外请求后端。实时数据继续使用折线图。

开发和生产环境均使用 `/_telemetry-api` 同源代理，仅匹配上述四个接口；健康代理和声纹服务请求地址不变，也可用 `VITE_API_BASE_URL` 覆盖。其他旧接口仍默认禁用，不影响其他页面现有接入。

## 告警管理接入（第三步）

告警管理包含“采集报警”“趋势报警”“声纹告警”三个具体列表，不再提供合并总览。采集硬限值报警、趋势报警和声纹告警分别查询、分别分页，避免不同业务口径混合统计。

采集报警通过独立 `src/services/alarms.js` 调用 `GET /api/analysis/alarms`，支持可选 `pointId`、`isActive`、`start`、`end` 和 `limit`（默认 200，范围 1–1000），不发送旧的模块/通道组合参数。模块与点位选择复用已迁移的只读元数据服务。默认不限定时段或状态，支持表格分页，点击「查看」在适配深色/亮色主题的弹窗中展示阈值、报警值及恢复值等详情；达到上限时提示查询可能截断。告警管理不展示或请求分析 Worker 状态。进入页面自动查询，可手动刷新，不新增后台轮询或写操作。

“趋势报警”通过 `GET /api/analysis/trend-alarms` 查询趋势报警事件。页面支持模块、点位、时间、活动状态和返回条数筛选，列表带分页；趋势变化折线图随查询结果同步更新，事件详情点击表格行后以浮层查看。

开发和生产环境中采集报警使用 `/_alarm-api`，趋势接口使用独立 `/_analysis-api` 白名单代理，均由服务器同源转发到采集服务，也可用 `VITE_API_BASE_URL` 覆盖。采集服务请求不携带声纹服务令牌，声纹服务的 `/alarm/page`、录音、样本类别和每日统计继续使用原请求方法、参数及鉴权。

## 趋势分析（第四步）

趋势分析页已接入 `GET /api/analysis/daily-limit-trends` 和 `GET /api/analysis/trend-insights`，按点位、时间范围和聚合分钟查询真实数据，展示每日最小值、均值、最大值、上下限、超限分钟以及后端风险洞察，不再使用静态趋势预览。

## Nginx 生产代理

生产站点的 `server` 块需配置以下 5158 白名单。趋势接口使用精确匹配，因此即使现有 SPA 规则写成 `location ^~ /`，也不会把 API 请求回退为 `index.html`。查询参数不参与 Nginx `location` 匹配，无需写入规则。

```nginx
location = /_analysis-api/api/analysis/daily-limit-trends {
    proxy_pass http://66.66.66.4:5158/api/analysis/daily-limit-trends;
    include /etc/nginx/snippets/equipment-api-5158.conf;
}

location = /_analysis-api/api/analysis/trend-insights {
    proxy_pass http://66.66.66.4:5158/api/analysis/trend-insights;
    include /etc/nginx/snippets/equipment-api-5158.conf;
}

location = /_analysis-api/api/analysis/trend-alarms {
    proxy_pass http://66.66.66.4:5158/api/analysis/trend-alarms;
    include /etc/nginx/snippets/equipment-api-5158.conf;
}

location ~ ^/(?:_health-api/api/health(?:/detail|/table-maintenance)?|_telemetry-api/api/(?:configuration/modules(?:/[^/]+/points)?|realtime/latest|telemetry/history)|_alarm-api/api/analysis/(?:alarms|status))$ {
    rewrite ^/_[^/]+(/api/.*)$ $1 break;
    proxy_pass http://66.66.66.4:5158;
    include /etc/nginx/snippets/equipment-api-5158.conf;
}
```

新建 `/etc/nginx/snippets/equipment-api-5158.conf`，内容如下：

```nginx
    proxy_http_version 1.1;
    proxy_set_header Host $proxy_host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Authorization "";
    proxy_set_header Cookie "";
    proxy_cache off;
    proxy_hide_header ETag;
    proxy_hide_header Last-Modified;
    add_header Cache-Control "no-store" always;
    proxy_intercept_errors off;
    proxy_connect_timeout 5s;
    proxy_read_timeout 15s;
    limit_except GET { deny all; }
```

然后在站点的 `server` 块中保留代理前缀兜底：

```nginx
location ~ ^/_(?:health|telemetry|alarm|analysis)-api(?:/|$) {
    return 404;
}
```

修改后依次执行 `nginx -t` 和 `nginx -s reload`。浏览器开发者工具中上述三个趋势接口应显示 `Content-Type: application/json`，响应体应分别包含 `days`、`insight`、`events`；若响应体是 `index.html`，说明请求仍被 SPA 静态规则接管。

### 产线状态监测首页

首页已合入现场 SVG 布局：右上 L 形 ZJ17 经储烟滚筒连接 YB25，左侧输送线接入竖向 YB55；YB55 垂直连接横向 YB65，YB65 与 YB95 在同一直线上。点击机组会同步切换左侧测点列表和右侧已配置参数的当前值；左侧按 MAX 风机、VE 风机、主电机等物理监测部位分组，合并该部位的振动、温度和声纹子测量，右侧以颜色和悬停提示显示正常、报警或待确认。点击分组进入 `/#/device?location=...` 对应详情页；未配置参数不计入主页当前值及测点列表，列表不再用采集模块名称代替物理点位。选中机组显示流水虚线，开启减少动态效果时取消动画。

图纸及几何布局由 `public/production-line/` 的 SVG 管理，监测身份及健康状态分别位于 `src/charts/productionLine.js` 和 `src/charts/productionLineStatus.js`。YB25 沿用原有 ZB25 的模块和采集器归属；YB65、YB95 尚无已确认的数据映射，显示未配置。后续接入需补充确认的模块/采集器映射。

主页保持一屏展示，当前值只展示已配置的数值采集参数，不显示声纹在线状态；声纹仍参与测点列表和设备连接状态。名称与数值同行，名称 16px、数值通常 28px。按可用宽度及数量分栏，参数较多时在当前值卡片内部滚动；告警列表分页。有效当前值在无活动报警且告警来源已成功返回时显示绿色，报警显示黄色；缺值、坏质量、离线或超过 10 秒未更新时显示“—”。声纹通道展示实际连接状态，不生成声纹诊断数值。顶栏专门表示采集设备连接状态：全部已返回的采集模块和声纹设备在线时显示“系统正常”，存在明确离线设备时显示“系统报警”，设备连接数据缺失或获取失败时显示待确认。测量值报警不改变连接状态顶栏，仍在机组、测点和告警列表中独立显示。

点击图中黄色报警状态会按机组过滤下方报警详情；报警与测点通过模块及真实点位标识匹配。告警接口查询上限为 1000 条，达到上限时不据此断言无报警。实时样本每 2 秒刷新，配置、声纹设备和告警每 30 秒刷新；离开首页会取消请求并清理计时器。右上角可暂停刷新、手动刷新或展开主题与账户设置。

首页隐藏“待确认”状态文字，保留报警、正常及离线等状态显示，数据有效性判断保持不变。点击有报警的测点分组会进入对应测点页，并自动打开该分组中首个报警参数的详情抽屉；无报警时沿用原有测点列表流程。自动打开请求只消费一次，关闭抽屉后刷新点位元数据不会重复打开。

### 机组概览的班次详情

点击主页当前值或机组概览测点卡片，在当前页面打开从右侧展开至左侧菜单栏边缘的历史抽屉，默认选中“当班”并立即查询该班次历史数据，不使用页面实时缓冲区作为初始详情。“当班”和“上一班”按钮立即切换并查询；开始、结束时间可编辑，编辑后进入自定义模式，点击查询执行。参数切换沿用当前时间范围并重新加载，关闭抽屉会取消请求，旧查询结果不能覆盖新查询。测点布局不再显示“CH 剔除状态”“高低速指示”“小包外观”三个状态按钮，其已有配置与采集身份保留。 历史抽屉每次打开、执行查询或切换实时视图时，通过单模块点位接口读取当前 Modbus 上下限，并在图中绘制带数值及单位的虚线基线。零值为有效限值，null 显示“未设置”且不画线；纵轴同时容纳采样和当前阈值。点击“刷新阈值”可获取外部更新，读取失败会提示并移除旧基线。基线表示当前配置，不代表历史采样发生时的阈值；声纹数据不套用 Modbus 限值。

班次沿用现有规则：早班 09:30–18:00，晚班 18:00–次日 02:00；02:00–09:30 期间当班指最近开始的晚班。班次详情请求完整的班次区间，显示后端已产生的数据，达到 100000 条接口查询上限时提示缩短范围。采集历史接口路径和参数约定保持不变；声纹测点默认查询同一班次区间内的录音。

### 机台指标与报警颜色

首页产线图上方展示“86#机台”和四个指标，并压缩图纸区域，保持整页无滚动，当前值卡片在参数较多时内部滚动。小盒产量、不合格数、NG 占比尚未接入，显示“—”。剔除状态使用现有 `PRESS01 / PRESS01-DI02 / PRESS01_DI02` 的“小包外观剔除按钮”信号，明确显示“按钮已触发 / 按钮未触发”；无有效实时样本时显示“—”，不将按钮信号解释为执行机构的实际状态。

首页告警列表和告警管理页提供“颜色设置”，支持黄色、红色，覆盖优先级为单条报警、警种、报警级别。配置按账户保存在当前浏览器，可恢复默认；仅改变显示，不修改报警级别、阈值或后端数据。严重报警默认红色，预警默认黄色，两种主题均提供对应的文字颜色。

### 参数名称、单位与两级点位配置

侧栏“参数配置”（`/#/settings/parameters`）逐项列出采集参数和声纹通道的后端名称、模块/设备、通道、参数编号、前端名称、后端/显示单位及当前值，可以按来源、配置状态和名称筛选。状态、自检及 DI 参数也列入目录；实时接口发现但参数目录尚未返回的值会补入列表。所有尚未保存对应关系的参数明确显示“未配置”，既有安装名称和归属仅作为编辑时的建议。

归属分为“大点位 → 被测点位”两级，例如“MAX 风机 → 电机驱动端轴承”。系统现有大点位保留为固定选项，也可添加大点位和被测点位；一个被测点位可关联振动、温度、压力或状态等多个参数。每个参数独立保存前端名称、显示单位和两级归属，保存后首页、机组监测、点位详情、趋势及报警显示使用同一份配置。测点详情页按大点位展示统一卡片网格，卡片顺序不依赖二级被测点位，隐藏“未配置参数”入口及其专属列表，旧链接回退到第一个正常大点位；机组监测卡片保持至少 150px 高度，参数较多时滚动浏览。

配置由前端保存在同源 localStorage 的 `equipment_dashboard_point_configuration_v1` 键中，同一浏览器中的所有账号共享，打开的同源标签页通过 storage 事件即时同步。关闭或刷新页面后保留，清除浏览器站点数据会删除配置。使用“导出配置”备份，使用“导入配置”替换当前配置并迁移到其他浏览器/电脑；导入前验证格式和两级归属，错误文件不覆盖现有配置。不同电脑之间目前通过配置文件迁移，没有自动同步接口。

采集参数按来源、模块、通道、参数编码识别，声纹通道按来源、设备编号、通道识别，名称变更不会串用配置。后端暂未返回已配置参数时保留对应关系。显示单位允许自定义和显式留空；修改单位只改标签，不换算采样值或阈值，也不修改后端的名称、身份或配置。所有采集接口仍使用原有 5158 代理且不携带声纹登录令牌；本次不增加后端接口。

新增的大点位支持编辑名称和所属机组，也支持删除。新增/编辑时对空格、大小写及全角字符进行归一化检查，阻止同一机组下的重复名称。删除时可将被测点位和参数迁移到其他大点位（同名被测点位合并，参数名称与单位保留），也可明确解除关联配置，使参数恢复“未配置”；后端参数与采样数据不会删除。系统固定大点位保留，不提供修改或删除操作。

### 卡片布局配置

机组概览、测点详情列表和详情弹窗的实时卡片提供“编辑布局”。进入编辑模式后，拖动卡片标题调整顺序，拖动右下角调整宽高；也可使用前移/后移按钮、宽度下拉框和高度输入框。宽度为四列网格中的 1–4 列，高度为 180–900px。标题拖动按钮支持左右方向键调整顺序，缩放按钮支持上下方向键调整高度。手机窄屏自动使用单列布局，桌面宽度配置仍保留。

“显示 / 隐藏卡片”中的勾选项控制每张卡片是否展示，卡片标题右侧的 × 也可以隐藏卡片。隐藏全部后可重新勾选，或点击“恢复默认布局”。“完成布局”退出编辑；修改自动保存，恢复默认会移除当前机组、监测位置或设备的自定义配置，机组概览恢复原来的分组布局，测点详情恢复统一卡片网格。恢复默认入口仅在编辑状态显示；机组概览和测点详情列表使用刷新按钮旁的布局图标进入编辑，编辑状态显示完成和恢复默认图标。

布局按机组、监测位置和设备分别保存在当前浏览器同源 localStorage 的 `equipment_dashboard_layout_v1:` 前缀下，同一浏览器中的账号共享，不自动同步到其他电脑。刷新或重新进入页面后恢复；清除站点数据会清除布局。名称修改不影响卡片身份，新增卡片自动追加，接口暂时缺少卡片时保留其布局设置。浏览器存储失败时页面显示提示，本次布局仍可使用但可能无法在刷新后恢复。

主页、测点详情列表和机组概览默认收起顶层标题栏。测点详情和机组概览在页面顶部保留点位/机组按钮与图标操作栏，右侧设置图标可展开主题、全屏和账户操作；切换到这些页面时重新收起。测点详情移除配置链接，暂停/恢复自动刷新和刷新数据使用图标；机组概览刷新也使用图标。图标提供悬停说明与无障碍标签，刷新过程中禁用按钮并显示旋转动画。

### 根据现场 PDF 重新生成产线图

图纸按 `1.pdf` 第一页的原始矢量路径顺时针旋转为横向，保留实际设备轮廓、偏置滚筒、折弯及回送线。设备对应经确认：右端 ZJ17、主电柜右侧整段 YB25；左下横向设备左部 YB95、右端双辊区域 YB65、下方竖向设备 YB55；细长设备为主电柜（以用户补充标注图为准）。原有监测映射、四台设备跳转、首页选择及报警联动继续使用。

运行 `node artifacts/production-line-real-layout/draw-pdf-layout.mjs` 同步生成制图目录和 `public/production-line/` 下三种 SVG；旧命令 `draw-real-layout.mjs` 也可使用。脚本只依赖 Node 内置模块，按脚本位置解析路径，可在任意工作目录运行，不需要原 PDF 或本机绝对路径。`pdf-layout-paths.json` 保存提取后的矢量源数据，`src/charts/productionLineLayout.js` 统一管理设备选区、标题和状态位置。可选 `--png` 使用已安装的 `sharp` 生成 PNG 预览；也可通过 `PRODUCTION_LINE_SHARP` 指定其模块 URL。

测点详情的趋势分析在同一测点刷新期间保留已有趋势和洞察，请求失败时显示错误并保留已成功的数据。父级刷新同一测点元数据不会重新发起分析，切换点位会清空旧结果。

趋势分析的上下限设置从当前模块点位配置读取 `minimumValue` / `maximumValue`，通过 `PATCH /_telemetry-api/api/configuration/points/{pointId}/limits` 保存到 5158 采集服务，同时提交两个字段。清空输入会传 `null` 取消该方向阈值；下限不能大于上限，允许相等；保存后重新查询趋势。纵轴范围使用图表自动计算。

部署时必须将本仓库 `nginx.conf` 中专用的 `location ~ ^/_telemetry-api/api/configuration/points/[0-9]+/limits$` 同步到生产站点的 `server` 块，并放在专用 API 的 404 兜底规则之前。此路由仅允许 PATCH，移除 `/_telemetry-api` 前缀后转发到采集服务 5158，清除声纹 Authorization 和 Cookie。不要复用只允许 GET 的 `equipment-api-5158.conf` 片段。修改部署配置后先执行 `nginx -t`，通过后执行 `nginx -s reload`；只更新前端 dist 不会修复此代理 404。无需重启采集服务，新配置加载后用于后续样本分析。

### 测点近期历史与整班缓存

当班缓存补取与手动历史查询均向采集接口发送本地日期时间，不转换为 UTC；递归分段时保留毫秒边界。旧版 UTC 查询产生的缓存块不再复用，首次打开会重新补取。

历史接口 `/api/telemetry/history` 的单次网络请求超时为 120 秒，前台查询和班次缓存补取使用相同设置；元数据及实时值请求仍为 10 秒。上级目录 `nginx.conf` 为历史接口单独配置 120 秒读取超时，部署时须同步该配置并重载 Nginx。切换查询或关闭页面仍会取消原查询，超过 120 秒显示历史查询超时提示。

测点详情独立页面及详情抽屉默认进入“历史曲线”，打开即查询当班完整区间的历史数据，支持当班、上一班及自定义时间，图表保留缩放与重置视图。采集点位直接使用历史接口结果，不依赖实时缓冲区、不受 300 个实时样本上限限制，也不追加每 2 秒的实时采样。离线设备仍可查询历史；错误、空结果和达到 100000 条上限会明确提示。声纹点位默认查询当班录音并展示历史波形；实时频谱只在主动切换频谱分析时启动。测点详情列表与机组概览的预览卡片仍保留近期采样展示。

登录后后台预热全部已配置的数值采集测点，排除声纹音频、DI、报警状态及自检点。沿用现有班次：白班 09:30–18:00，夜班 18:00–次日 02:00；02:00–09:30 沿用最近夜班。当前班次截至当前时间的原始采样按小时写入 IndexedDB（`equipment_shift_history_v1`），按后端地址、账户、pointId 和班次隔离；保留原始数值及质量，不进行降采样。页面展示已完成测点数量，失败项会自动重试。

机组概览、测点详情、历史列表和班次曲线使用同一个历史接口入口。当前班次优先复用缓存，未完成区段从 5158 原历史接口补取；历史请求最多并发 2 个，后台逐点预热，为前台查询保留请求能力。达到单次 10000 条上限时递归拆分时间段，全部子段读取成功后才写入完整缓存。后台每轮完成后 60 秒继续补取最新区段，并重读尾部 2 分钟以接纳延迟入库及修正；已结束区段缓存 30 分钟后重新读取，以更新更早的后端补写。内存仅保留最近使用的 24 个小时块，图表不加载整班缓存到实时缓冲。

刷新浏览器可复用已写入的班次缓存；换班后下一轮自动清理旧班缓存。跨班次及自定义范围超出当前班次时仍按原接口查询。缓存写入失败会提示并退回有限内存缓存，缺失区段仍请求接口；因此缓存不代表离线数据已完整备份。退出登录会取消预热和在途请求。采集请求仍使用 `/_telemetry-api`，不携带声纹登录令牌，也不新增后端接口。

产线 SVG 型号字体为 40px，中文名称为 28px，状态文字为 24px；三种图纸样式同步生成。卷接机统一标识为 `ZJ17`；读取旧版浏览器配置或导入配置时自动转换旧机组归属，机组概览也兼容读取旧存储键下的布局。

## 首页实时运行信息

首页生产状态每 1 秒请求 GET /api/runtime-info/latest，仅展示 summary.brand（牌号）、checkCount（小盒产量）、checkNg（NG数）、ngP（NG率，直接添加 %，保留两位小数）。进入首页立即读取，慢请求不重叠，离开首页取消请求并停止轮询。失败保留上次数据并提示过期，离线、无数据和未启用状态单独提示。其他页面不接入。

使用独立 /_runtime-api 同源代理，Vite 开发/预览与 nginx.conf 仅放行该端点并转发至 5158，不携带声纹登录令牌。可使用 VITE_API_BASE_URL 覆盖地址。生产部署需同步更新 Nginx 配置并重载。
