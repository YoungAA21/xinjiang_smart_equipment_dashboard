# 智能设备健康管理平台大屏

基于 Vue 3、Vite、ECharts 和 lucide-vue-next 实现的静态数字化大屏原型。

## 本地运行

开发和构建均使用真实后端数据，需要后端服务可用并使用真实账号登录。

```bash
npm install
npm run dev
```

## 环境与构建

使用 Node 22.12+（或满足 Vite 要求的更新版本）。参考项目的公共配置与构建配置分离方式，本项目使用三套环境：

| 用途 | 命令 | 环境文件 | 产物 |
|---|---|---|---|
| 本地开发 | `npm run dev` | `.env.development` | 开发服务器 |
| 联调 | `npm run debug` | `.env.debug` | 开发服务器 |
| 调试打包 | `npm run build:debug` | `.env.debug` | `dist-debug/`，不压缩，包含源码映射 |
| 调试产物预览 | `npm run preview:debug` | `.env.debug` | 预览 `dist-debug/` |
| 生产打包 | `npm run build` | `.env.production` | `dist/`，压缩，无源码映射 |
| 生产产物本地预览 | `npm run preview` | `.env.production` | 预览 `dist/`，通过 Vite 代理访问后端 |

开发、调试、打包和预览统一使用一个 `vite.config.build.js`，通过 `--mode` 读取不同环境文件。

生产环境将 `dist/` 部署到现有 Nginx 的站点目录，接口由 Nginx 转发。详细地址配置、覆盖优先级和部署步骤见 [环境与部署说明](docs/environments.md)。

```bash
npm run build
```

## 分级报警

采集报警继续使用 `GET /api/analysis/alarms`，通过现有 `/_alarm-api` 同源代理访问，不携带声纹登录令牌或 Cookie。支持 `pointId`、`isActive`、`start`、`end`、`limit` 原查询参数。

按 `alarmKey` 区分 `GradedLimit` 分级报警、`Composite:` 组合报警和空标识的传统上下限报警。分级严重度 `1/2/3` 对应损坏（红）、告警（橙）、提示（黄），优先展示后端 `levelName`，缺失时按严重度兼容。自定义显示颜色仍保留，并新增橙色选项。

采集报警列表默认显示全部报警类型，不提供类型和方向筛选。等级使用“全部报警、损坏、告警、提示”四张卡片切换，数量对应本次查询已获取的记录，包含所选恢复状态。等级筛选不作为后端查询参数发送。列表和详情展示方向、触发阈值、恢复阈值，达到返回上限时在分页栏标记。传统报警的空字段正常显示为缺省值，仍展示原上下限。页面保留数据、筛选和实际错误信息，去除辅助提示小字。

列表默认查询当前告警，未限定时间时每 3 秒自动刷新，不显示刷新勾选框或提示；历史、隐藏页签、浏览器后台、查询未结束及详情打开时暂停自动刷新。详情使用打开时的记录，关闭后恢复当前告警轮询。历史可选择全部状态或已恢复并指定时间范围。首页每 2 秒查询活动报警，按分级严重度优先展示；数据大屏同步展示分级信息。

同一测点升降级产生的流水按 `alarmId` 分别保留，不按点位合并。时间按 ISO 日期解析并转为用户本地时间，触发数值与实时值分开展示，触发和恢复阈值不混用。

## 首次加载状态

首页、机组监测、测点列表及详情、采集/趋势报警、网关通讯、参数配置、监听、录音、趋势/频谱分析和报告配置，在首次读取各自的数据时，在列表、图表和统计数值所在位置显示骨架占位，不使用遮罩。首次请求无论成功或失败都会结束加载，失败继续使用原有错误与重试入口。

加载状态按页面实例记录首次读取完成状态，后续手动刷新和定时轮询不会重新显示占位，也不会清空已显示内容。历史图表仅在尚无样本且正在首次预读时显示局部加载；已有样本时的实时更新不遮挡曲线。登录、保存限值、报告生成/读取等操作沿用按钮或进度条反馈；纯静态图纸和本地配置操作不增加人为等待。

共用 `src/components/DataLoading.vue` 展示原位骨架，标题、筛选和操作栏保持可用；颜色跟随亮暗主题，并支持减少动画偏好。

## 登录 API 配置

直接修改对应的 `.env.development`、`.env.debug` 或 `.env.production`。个人覆盖配置可写入对应的 `.env.[mode].local`。默认登录通过同源 `/auth/login`，通常不需要设置独立地址。需要独立登录服务时，通过 `VITE_LOGIN_API_URL` 指定完整接口地址，例如：

```dotenv
VITE_LOGIN_API_URL=http://66.66.66.4:18080/auth/login
```

也可使用同源路径，例如 `VITE_LOGIN_API_URL=/auth/login`。留空时使用 `VITE_NEW_API_BASE_URL` 对应服务的 `/auth/login`；该基址也留空时，浏览器跟随页面源（不自行追加 18080 端口），由开发环境的 Vite 或生产环境的 Nginx 转发。登录仍以 POST 表单提交账号和密码，不携带已有登录令牌。

开发环境修改 `.env` 后须重启 Vite。生产环境可通过 `.env.production` 设置部署地址，修改后须重新构建并部署；直接修改已部署静态文件旁的 `.env` 不会生效。不要将账号、密码或令牌放入 `VITE_*` 配置。

## 数据展示大屏

登录后通过侧栏“数据展示大屏”进入 `/#/data-screen`。大屏沿用亮暗主题，自动隐藏侧栏并压缩顶部导航，以九区网格展示采集模块、全部点位实时值、所选点位曲线、系统检查与管道、数据表分区与缓存、硬限值和趋势报警、原始历史数据、每日限值趋势及趋势洞察。仅使用 5158 采集服务，不请求声纹设备、录音或频谱服务，也不发送其登录令牌。

实时采样每 2 秒刷新，总览、点位元数据及分析每 60 秒刷新；支持暂停、手动刷新、点位搜索与切换，并复用顶部主题与全屏按钮。曲线只积累本次访问的真实采样；历史默认查询最近 10 分钟（最多 5000 条），趋势与洞察查询最近 30 天，每类报警最多 1000 条，达到上限时提示可能截断。面板内部滚动展示全部已获取记录，点击模块、检查、数据表、报警及详情按钮查看完整字段。各来源显示成功更新时间，失败保留旧数据并提示；离开页面停止定时器并取消请求。大屏优先适配 1366×768 及以上桌面，较小高度采用网格内部滚动。

运行环境须满足 Vite 的 Node 要求（例如 Node 22.12+ 的 22 系列）。Windows 安装使用 `npm ci --include=optional`，确保 Rolldown 原生依赖完整。

## 说明

「报告配置」（`/#/reports`）设置采集范围与振动、温度、负压 / 压力三类重点指标，生成已结束班次或自然日的固定 HTML 报告。「报告查看」（`/#/reports/view`）默认打开最近已结束的上一班，可切换班次、日期、日报或已存报告，并下载可离线阅读、打印的 HTML 文件。首次查看未存档周期时按已保存配置汇总，已存报告直接读取快照；配置页可重新生成同周期报告。配置与最近 60 份报告按登录用户保存在当前浏览器，尚无服务端定时生成或跨浏览器共享。仅复用现有采集历史、告警与趋势接口，没有新增后端接口。缺数、失败和查询上限分别提示；当前阈值重算的越限不替代历史正式告警。详见 [设备报告说明](docs/equipment-reports.md)。

- 页面入口：`src/App.vue`
- 图表封装：`src/components/EChart.vue`
- 全局样式：`src/style.css`
- 首页使用真实健康接口数据，设备监控整合采集与声纹两类业务后端，其他页面按原有接入方式运行。

## 健康状态接入（第一步）

首页请求采集服务的 `GET /api/health`、`GET /api/health/detail`、`GET /api/health/table-maintenance`，同时复用声纹服务的 `GET /monitor/devices`。默认每 15 秒刷新，可暂停或手动刷新，离开首页即停止轮询并取消未完成请求。各业务独立处理，超时为 10 秒。健康详情返回 HTTP 503 时仍展示 JSON 检查结果；请求失败保留上次数据并明确提示。

本地开发通过 `/_health-api` 同源代理连接 `API_PROXY_TARGET`，默认 `http://66.66.66.4:5158`，代理仅匹配上述三个健康接口，不转发其他旧接口或 18080 接口。生产环境同样请求 `/_health-api`，由 Nginx 转发到 `equipment_backend`。需更换开发后端时，在 `.env.development.local` 设置 `API_PROXY_TARGET`；需要浏览器直接访问独立服务时，才设置 `VITE_API_BASE_URL`。

`src/services/health.js` 使用独立请求通道，不携带 18080 服务的登录令牌。首页的新设备列表通过现有 `api.getMonitorDevices` 使用 18080 的登录令牌；没有新增监听会话或音频连接。未配置 `VITE_NEW_API_BASE_URL` 时，开发环境通过 Vite 的 `ACOUSTIC_PROXY_TARGET`、生产环境通过 Nginx 的 `soundvoice_backend` 同源转发，避免浏览器跨域请求；监听 WebSocket 和录音地址也使用同一入口。登录、鉴权和其他页面业务接口保持不变。其他旧接口继续由 `VITE_LEGACY_API_DISABLED` 控制，默认停用。

首页展示心跳、检查明细、数据库及点位状态、模块在线状态、历史/聚合表分区、缓存、配置文件和表维护记录。首页不使用静态预览数据；系统健康与模块在线状态分别统计。

首页主视图采用图表布局：检查通过率仪表盘、模块在线环图与可点击状态矩阵、检查分类条形图、分区覆盖热力图、缓存环图、维护前后分区柱状图及数据管道示意。完整表格保留在底部“完整诊断明细”，展开时才加载。不生成模拟趋势，零缓存显示空环，并适配亮暗主题和减少动态效果设置。

设备区域整合 `runtimeModules.statuses[]`（采集模块）与 `/monitor/devices`（声纹设备），总览卡片按两边已获取记录相加，环图与状态矩阵支持全部/采集模块/声纹设备筛选。采集模块使用 `isOnline`，声纹设备使用 `online`，字段缺失计为未知；设备下的网关、通道只展示连接情况，不重复计数。使用来源、协议和字符串 ID 区分记录，未建立跨系统映射前不跨来源去重。每个来源显示更新时间和失败/过期状态，未返回的数据不冒充零设备。健康检查、分区、缓存、点位与队列仍只描述采集服务。

```bash
node --experimental-vm-modules --test tests/*.test.mjs
npm run build
```

## 设备监控接入（第二步）

设备监控按业务整合采集模块和声纹设备，可筛选来源和切换设备。声纹服务继续调用原有 `GET /monitor/devices`，保留网关、通道字段及原鉴权，仅进入页面或手动刷新时获取，不创建监听会话；声纹实时波形仍使用原有频谱分析功能。

采集服务使用独立的 `src/services/telemetry.js`，接入以下四个只读接口，不携带声纹服务令牌：

- `GET /api/configuration/modules`：模块目录每 15 秒刷新。
- `GET /api/configuration/modules/{moduleId}/points?includeLatest=false`：切换模块时获取点位和 `pointId`。
- `GET /api/realtime/latest`：选中采集模块时每 2 秒刷新，可暂停。按模块、通道、点位编码匹配元数据，每个点位保留最近 300 个实际采样时间点，重复时间戳不追加，零值正常显示，超过 15 秒的采样间隔断线显示。折线只积累本次页面访问的数据，不补造历史。
- `GET /api/telemetry/history?pointId=...&start=...&end=...&limit=...`：使用本地时间和 `pointId` 查询原始数据表格。进入历史模式或在历史模式切换点位时，自动查询当前时间之前 10 分钟，默认最多 5000 条；也可手动调整时间范围查询。查询上限为 1–100000，达到上限时提示可能截断。

两套接口分别显示加载错误，不因一侧失败清空另一侧数据。切换点位会清除旧历史，过期请求不能覆盖新选择，离开页面停止轮询并取消请求。

历史查询结果仅用表格展示，包含采集时间、原始精度数值、单位和原始质量值；默认最新优先，支持时间排序与每页 20/50/100 条分页，分页不额外请求后端。实时数据继续使用折线图。

开发和生产环境均使用 `/_telemetry-api` 同源代理，仅匹配上述四个接口；健康代理和声纹服务请求地址不变，也可用 `VITE_API_BASE_URL` 覆盖。其他旧接口仍默认禁用，不影响其他页面现有接入。

## 告警管理接入（第三步）

告警管理展示“采集报警”“趋势报警”两个列表，分别查询、分别分页。声纹告警页签已隐藏，进入告警管理不再请求声纹告警列表、关联录音、样本类别或每日统计。

采集报警通过独立 `src/services/alarms.js` 调用 `GET /api/analysis/alarms`，支持可选 `pointId`、`isActive`、`start`、`end` 和 `limit`（默认 200，范围 1–1000），不发送旧的模块/通道组合参数。采集报警和趋势报警统一按当前参数配置的“机组 → 机型 → 大点位 → 被测点位 → 参数”分类、筛选，默认查询全部已配置采集参数，不包含未配置的后台点位或模块级事件。通过只读点位目录确认真实 `pointId`，将所选设备范围展开为逐点查询（最多三个并发），合并去重后按开始时间倒序分页；每点请求与合并结果均受所选条数上限约束，任一点达到上限或合并后截断都会提示结果可能不完整。点位失效或任一查询失败会明确报错，不退回全局告警查询；同一范围刷新失败保留上次成功结果及已应用筛选。选择具体机组、机型或点位后，后续下拉框会逐级自动选中首个有效选项并查询；选择“全部”时清空下级选择以保留范围查询。切换设备范围、修改参数归属会清理旧结果并重新查询。默认不限定时段或状态，点击「查看」展示设备点位归属、原始模块标识、阈值、报警值及恢复值等详情。告警管理不展示或请求分析 Worker 状态。进入页面自动查询，可手动刷新，不新增后台轮询或写操作。

“趋势报警”通过 `GET /api/analysis/trend-alarms` 查询趋势报警事件。页面支持上述设备点位层级、时间、活动状态和返回条数筛选，列表带分页；趋势变化折线图可单独选择参数，按参数身份和事件单位分组，避免温度、振动或历史不同单位的值混接成同一曲线。事件详情点击表格行后以浮层查看。分类使用当前配置，调整归属后历史事件也按当前归属展示；事件的阈值、数值、状态和已有单位保留后端数据。

开发和生产环境中采集报警使用 `/_alarm-api`，趋势接口使用独立 `/_analysis-api` 白名单代理，均由服务器同源转发到采集服务，也可用 `VITE_API_BASE_URL` 覆盖。采集服务请求不携带声纹服务令牌。声纹告警接口方法保留供后续恢复，当前告警管理不调用。

## 实时监听

“设备监测 → 实时监听”（`/#/realtime-listen`）参考声纹项目的 `RealtimeMonitorView.vue`，按当前大点位选择音频通道。通道归属优先采用参数配置，未配置时复用现有采集器 IP 与大点位映射；同一大点位多个通道默认选中首个，可手动切换。无通道、离线或连接状态未知时不启动监听。录音管理导航已隐藏，旧地址 `/#/recordings` 重定向到实时监听，保留原录音页面源文件及接口方法。

进入页面只调用 `GET /monitor/devices`，每 15 秒刷新设备及通道状态，超时 10 秒；不自动播放。点击“开始监听”才创建 `POST /monitor/sessions` 独立会话，指定一个真实通道、可选图形帧率和 `pcm_s16le`。信号与音频分别连接响应的 `websocketPath`、`audioStreamUrl`，使用现有声纹鉴权。复用现有 `/monitor` 代理；生产反向代理须支持该路径的 WebSocket Upgrade，不向采集服务附带声纹令牌。

提供时域、频域、瀑布图、连接状态、实际采样率、电平、音量和静音。PCM16 小端单通道音频积累 1 秒后连续播放，断流或采样率改变时重新缓冲，积压超过 10 秒明确报错并停止。切换大点位或通道、连接异常及离开页面均关闭两路 WebSocket、停止 Web Audio 并删除监听会话；创建中的会话若晚返回也会删除，旧回调不得污染新点位。离开页面取消目录请求并清理计时器。

## 趋势分析（第四步）

趋势分析页已接入 `GET /api/analysis/daily-limit-trends` 和 `GET /api/analysis/trend-insights`，按点位、时间范围和聚合分钟查询真实数据，展示每日最小值、均值、最大值、上下限、超限分钟以及后端风险洞察，不再使用静态趋势预览。

2026-09-03 曾对旧地址 `192.168.31.158:5158` 做只读联调：硬限值报警、每日限值趋势、趋势洞察和趋势报警接口均返回 HTTP 200。当前后端地址为 `66.66.66.4`。

使用 `npm run preview` 运行生产构建时，Vite Preview 已配置与开发服务器相同的 5158 白名单代理。修改 `vite.config.build.js` 后必须停止并重新启动 Preview 进程，仅重新执行 `npm run build` 不会更新正在运行的代理配置。

## Nginx 生产代理

生产站点的 `server` 块需配置以下 5158 白名单。趋势接口使用精确匹配，因此即使现有 SPA 规则写成 `location ^~ /`，也不会把 API 请求回退为 `index.html`。查询参数不参与 Nginx `location` 匹配，无需写入规则。

```nginx
location = /_analysis-api/api/analysis/daily-limit-trends {
    proxy_pass http://66.66.66.4:5158/api/analysis/daily-limit-trends;
    include /etc/nginx/snippets/equipment-api-5158.conf;
}

location = /_analysis-api/api/analysis/trend-insights {
```

采集参数按来源、模块、通道、参数编码识别，声纹通道按来源、设备编号、通道识别，名称变更不会串用配置。后端暂未返回已配置参数时保留对应关系。显示单位允许自定义和显式留空；修改单位只改标签，不换算采样值或阈值，也不修改后端的名称、身份或配置。所有采集接口仍使用原有 5158 代理且不携带声纹登录令牌；本次不增加后端接口。

### 测点近期历史与整班缓存

当班缓存补取与手动历史查询均向采集接口发送本地日期时间，不转换为 UTC；递归分段时保留毫秒边界。旧版 UTC 查询产生的缓存块不再复用，首次打开会重新补取。

历史接口 `/api/telemetry/history` 的单次网络请求超时为 120 秒，前台查询和班次缓存补取使用相同设置；元数据及实时值请求仍为 10 秒。上级目录 `nginx.conf` 为历史接口单独配置 120 秒读取超时，部署时须同步该配置并重载 Nginx。切换查询或关闭页面仍会取消原查询，超过 120 秒显示历史查询超时提示。

测点详情独立页面及详情抽屉默认进入“历史曲线”，打开即查询当班完整区间的历史数据，支持当班、上一班及自定义时间，图表保留缩放与重置视图。采集点位直接使用历史接口结果，不依赖实时缓冲区、不受 300 个实时样本上限限制，也不追加每 2 秒的实时采样。离线设备仍可查询历史；错误、空结果和达到 100000 条上限会明确提示。声纹点位默认查询当班录音并展示历史波形；实时频谱只在主动切换频谱分析时启动。测点详情列表与机组概览的预览卡片仍保留近期采样展示。

登录后后台预热全部已配置的数值采集测点，排除声纹音频、DI、报警状态及自检点。沿用现有班次：白班 09:30–18:00，夜班 18:00–次日 02:00；02:00–09:30 沿用最近夜班。当前班次截至当前时间的原始采样按小时写入 IndexedDB（`equipment_shift_history_v1`），按后端地址、账户、pointId 和班次隔离；保留原始数值及质量，不进行降采样。页面展示已完成测点数量，失败项会自动重试。

机组概览、测点详情、历史列表和班次曲线使用同一个历史接口入口。当前班次优先复用缓存，未完成区段从 5158 原历史接口补取；历史请求最多并发 2 个，后台逐点预热，为前台查询保留请求能力。达到单次 10000 条上限时递归拆分时间段，全部子段读取成功后才写入完整缓存。后台每轮完成后 60 秒继续补取最新区段，并重读尾部 2 分钟以接纳延迟入库及修正；已结束区段缓存 30 分钟后重新读取，以更新更早的后端补写。内存仅保留最近使用的 24 个小时块，图表不加载整班缓存到实时缓冲。

刷新浏览器可复用已写入的班次缓存；换班后下一轮自动清理旧班缓存。跨班次及自定义范围超出当前班次时仍按原接口查询。缓存写入失败会提示并退回有限内存缓存，缺失区段仍请求接口；因此缓存不代表离线数据已完整备份。退出登录会取消预热和在途请求。采集请求仍使用 `/_telemetry-api`，不携带声纹登录令牌，也不新增后端接口。

产线 SVG 型号字体为 40px，中文名称为 28px，状态文字为 24px；三种图纸样式同步生成。卷接机统一标识为 `ZJ17`；读取旧版浏览器配置或导入配置时自动转换旧机组归属，机组概览也兼容读取旧存储键下的布局。

## 首页实时运行信息

首页生产状态每 1 秒请求 GET /api/runtime-info/latest，仅展示 summary.brand（牌号）、checkCount（小盒产量）、checkNg（NG数）、ngP（NG率，直接添加 %，保留两位小数）。进入首页立即读取，慢请求不重叠，离开首页取消请求并停止轮询。失败保留上次数据并提示过期，离线、无数据和未启用状态单独提示。其他页面不接入。

使用独立 /_runtime-api 同源代理，Vite 开发/预览与 nginx.conf 仅放行该端点并转发至 5158，不携带声纹登录令牌。可使用 VITE_API_BASE_URL 覆盖地址。生产部署需同步更新 Nginx 配置并重载。

报警等级卡片按本次查询返回的同一批记录统计（当前、已恢复或全部状态）：全部报警 = 损坏 + 告警 + 提示 + 上下限告警 + 其他告警。只有 `GradedLimit` 且 `severity` 为 1/2/3 的记录归入对应等级；旧版上下限报警归入上下限告警；组合报警和无法识别等级的记录归入其他告警，该卡片仅在存在对应记录时显示。列表颜色可以自定义，颜色不作为等级判断依据。
