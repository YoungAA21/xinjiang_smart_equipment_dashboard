# 计划 C：后端事实来源、DI 可靠记录和处理闭环

状态：待分配到后端仓库执行。本仓库没有后端实现，不能用前端缓存代替本计划。负责人：后端；现场/采集负责人确认规则。共用 [S0 契约](README.md)。

## C1：稳定身份、持久化及聚合查询

1. 核实 5158 采集/趋势和 18080 声纹的原始字段、分页、恢复语义、增量同步能力、历史保留期、时间与时区。形成来源能力表及真实脱敏样本。
2. 选择已有后端扩展点或聚合服务，持久化稳定 source + sourceEventId、来源 revision/同步水位与事件详情。无稳定 ID 的来源由服务端建立稳定映射，不能每次拉取重新生成。
3. 聚合活动快照、跨来源待办和历史分页。活动总数不依赖历史 limit；快照带版本、来源健康、完整性、lastProcessedAt。按来源失败独立降级，接口整体成功不能掩盖某来源失败。
4. 历史查询支持机组/模块/点位和双维状态筛选、稳定排序、分页/游标；处理记录必须能覆盖恢复后的事件和不再出现在上游列表中的事件。
5. 固化机组/测点关联与未归属队列；声纹录音/样本类别有稳定父子身份。历史事件保留阈值、单位、规则版本及时间。
6. 输出接口契约和真实样本给 B/D，更新部署代理与 README。5158 不接收声纹令牌，处理写接口使用明确的授权边界。

## C2：可靠的源事件与 DI

1. 对六路 DI 逐一确认用途：工况/异常、有效极性/边沿、最短有效脉冲、防抖、恢复及启动为高电平的行为。未知通道不直接沿用“1=故障”。
2. 在采集侧/后端按原始采样或硬件边沿事件生成和持久化，不以浏览器 latest 的两秒轮询作为记录源。
3. 验证上游采样周期能够覆盖最短目标脉冲；若不能，需硬件锁存、事件缓冲或更快采样。仅把轮询代码从前端移到后端不能证明不漏脉冲。
4. 保存 per-point 状态、最后有效采样时间/序列和当前事件身份；重启可恢复。按规则处理坏质量、过期、未来和乱序采样；缺数/断线不生成假恢复。
5. 首次高电平可按确认后的规则创建“首次观测仍活动”事件，使用首次可靠观测时间，不虚构更早触发时间。停机期间存在无法覆盖的采样区间时显式记录覆盖缺口。
6. 核实硬限值与趋势已有触发/恢复规则，补齐 S0 要求的边界、防抖/回差、样本覆盖和规则版本。已有后端已实现的能力复用并提供证据，不重复实现。
7. 重复采样不重复事件；恢复后再次触发创建新事件。规则修改仅影响新判定，历史阈值/单位快照保持不变。

## C3：人工处理和审计

1. 在服务端实现确认、追加处置、关闭、审计查询，与条件状态独立存储。事件、操作记录和审计关联须可在服务重启后恢复。
2. 确认不会消除活动状态；恢复不会代替确认；关闭校验解决依据，持续异常无恢复或合规人工核验不得关闭。一次性事件按其 recordType 处理。
3. 声纹已有“已处理”只能通过经确认的映射接入。需决定统一中心与上游谁拥有处理状态；若双向同步，明确幂等、失败补偿与冲突规则。最小方案可由统一中心拥有处理状态、上游原样展示，避免双主写入。
4. 服务端校验权限，操作者从有效身份获取；支持 expectedRevision、idempotencyKey，防止重试重复操作和多人覆盖。非法转换、失去权限和冲突返回可识别错误。
5. 审计保存事件键、操作者、动作、前后状态、时间、说明、规则版本及人工核验依据。接口成功须代表已持久化，不能先返回成功再尽力写入。

## C4：切换与回滚

1. 以同一组源采样做影子比对，解释前后端 DI 的差异；识别采样覆盖缺口，不能只比较事件数量。
2. 旧 localStorage 事件保留为 `digital-local` 历史归档，不冒充后端正式事件，不自动覆盖正式处理状态。不可靠的旧记录需保留其来源限制。
3. 后端正式事件启用时停止浏览器生成 DI 事件；共享中心按来源稳定 ID 去重，明确切换时间及活动事件归属，不让两个写入者同时计数。
4. 配置可回滚，但正式后端历史和审计保留。回滚若恢复浏览器记录只能标为降级模式，不能宣称具备后台可靠留存。
5. 对统一接口、来源同步延迟、持久化失败和采样缺口提供可观察的状态；D 验证这些异常能在前端显示。

## 验收证据

关闭浏览器仍能完整记录目标脉冲；采集进程重启不重复/丢失活动事件；历史超过 1000 条仍保留早期活动事件；两名操作者并发写入不丢审计；完整事件可跨服务重启追溯。证据包括原始采样/边沿、数据库事件、接口返回和审计记录的同一稳定身份。

在后端仓库、部署环境或来源能力尚未提供时，C 可继续完成契约/规则/样本准备，但最终完成状态必须保持待实现/待验证。
