# 计划 D：契约、回归与真实链路验收

状态：待实施。负责人：测试/技术负责人；现场负责人参与业务验收。共用 [总计划与放行清单](README.md)。

## D1：先准备可复用证据

1. 建立四来源脱敏样本及预期规范化结果，包含：持续异常、一次性声纹事件、无恢复能力、未知严重级别、相同裸 ID、超大字符串 ID、缺点位身份、模块级事件、重复/乱序恢复。
2. 与现场负责人确认六路 DI 规则表和硬限值/趋势规则。只记录已确认的值，未确认项显式标待定，不替业务决定正常电平。
3. 用符合 Vite 引擎要求的 Node 运行当前测试和构建，记录版本与原始输出。此前三项失败需重现并判定为实现问题或旧测试预期；调整测试必须有需求依据，不通过跳过/删除测试隐藏失败。
4. 为 C 的待实现接口提供契约夹具与可控延迟/错误。夹具成功仅证明调用/呈现正确，不证明后端可靠性。

## D2：并行验证矩阵

| 场景 | 预期 | 证据来源 |
| --- | --- | --- |
| 四来源分别产生事件 | 首页/机组/点位/管理页按同一范围显示，未归属明确展示 | 服务端样本 + 各页对应稳定 ID |
| A、B 两事件录音请求乱序 | 选 B 始终显示 B 的录音与样本类别，含第 10 条之后的录音 | 可控异步测试 + 浏览器操作 |
| 改筛选尚未查询/查询失败 | 列表、总数、已应用条件保持一致，失败保留旧数据并告知 | 组件/服务集成测试 |
| 历史超过 1000 条且最早事件仍活动 | 全局仍包含该活动事件，历史分页可遍历 | 后端集成测试 + 前端计数 |
| 活动快照分页中断或版本改变 | 不把部分结果发布为完整正常状态 | 快照协议测试 |
| HTTP 成功但上游同步水位停止 | 来源陈旧；不能显示整体正常 | 假时钟测试 + 联调 |
| 旧/未来/乱序/坏质量/缺失样本 | 不假触发或假恢复；必要时显示未知/覆盖缺口 | 源判定单元与集成测试 |
| 模块级事件没有点位身份 | 只影响模块/机组，不让每个测点假报警 | 模型测试 + 页面 |
| A 确认、B 查看 | B 刷新后状态一致；仍活动则活动数不减 | 两会话真实接口 |
| 两人同 revision 并发处理 | 成功或明确冲突，审计完整，无静默覆盖 | 后端并发测试 |
| 重复提交/网络重试 | 一次有效操作、一次对应审计，返回结果一致 | 幂等接口测试 |
| 先恢复后确认 | 活动数减少，待办保留；确认、处置后可关闭 | 真实接口 + 跨页检查 |
| 声纹一次性事件/无恢复能力 | 按约定路径完成处置和关闭，不伪造恢复 | 来源契约 + 审计 |
| 断网、切页、退出、切账户 | 请求清理、无旧响应回填、无跨账户残留 | 前端生命周期测试 |
| 改阈值/改单位后查看旧事件 | 旧事件阈值、规则版本、单位不变 | 持久化与详情测试 |
| 双主题与颜色覆盖 | 严重级别可读、状态有文字、无纯颜色依赖 | 两主题截图/人工核验 |

D 负责新增跨链路 `tests/alarmClosure.test.mjs` 与验收记录；A/B 各自负责其任务指定的聚焦测试，避免同时修改同一个测试文件。

## D3：正式放行演练

1. 使用已确认规则的测试设备/信号，记录采样或边沿和后端事件身份。
2. 关闭全部浏览器，触发、维持、恢复信号；重新打开后必须可完整追溯。对最短目标 DI 脉冲单独验证采集能力。
3. 持续活动期间重启采集/聚合服务，验证事件延续、未知区间展示、无重复与假恢复。
4. 两名操作员分别完成确认、追加处置、并发冲突、恢复核验与关闭；验证审计及不同会话看到一致状态。
5. 制造一个来源失败、同步延迟、写入失败、401/403、网络超时；界面不得假绿、假成功、错录音或丢掉待办。
6. 验证 C4 单一 DI 写入者、旧缓存归档、版本切换和回滚，保存前后计数及稳定身份对照。

每条证据至少包含环境/版本、规则版本、源事件身份、时间、步骤、期望、实际结果、截图或接口/日志引用、验收人。不能仅记录“测试通过”。

## 命令与完成门槛

使用符合仓库要求的 Node（22.12+ 的 22 系列，或满足 Vite 引擎的其他版本）；宿主默认 Node 20.18.1 不适用。

```text
node --experimental-vm-modules --test tests/*.test.mjs
npm run build
```

完成标准：新旧回归均通过，生产构建成功；总计划所有最终清单项有直接证据；真实后端/采集链路与两主题验收完成。未提供后端环境、未确认声纹语义、未知 DI 规则或采集覆盖缺口均须列为未完成项，不能以夹具替代放行。
