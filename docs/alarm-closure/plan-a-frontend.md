# 计划 A：页面、查询和处理交互

状态：待实施。执行前阅读 [共同契约](README.md#s0共同约定所有计划必须使用)。负责人：前端 A。

## A1：立即修复可信度

1. 首页连接文案改为明确的采集连接状态；移除固定“各项设备均运转正常”。两项剔除状态绑定经确认的实时信号及新鲜度，尚未确认或不可用时显示待确认。
2. 分别显示触发值、当前值、触发时下限/上限和事件单位；读取 thresholdMin/thresholdMax，不把 alarmValue 称为当前值。空值不能变成 0。
3. 声纹告警列表、录音、样本类别分别增加请求取消与代次校验；请求身份需包含父告警/文件身份；离开页面、切换账户时取消请求。补齐服务调用 signal 支持。
4. 声纹录音当前只取前 10 条，需要提供翻页/加载更多，且显示真实总数，保证完整追溯；无权限、请求失败与确实无录音分别展示。
5. 趋势列表达到 limit 时提示可能截断；来源失败保留旧数据同时显示更新时间和失效状态。

A1 不依赖后端新增接口。最小验收：A→B 快速切换且 A 最后返回，仍只展示 B 的录音/类别；离页后的结果不回填；缺失数据不会显示正常；首页阈值与详情一致。

## A2：接入一致查询与最小处理入口

1. 采集/趋势提供“全部”入口。现有接口不支持的模块级查询必须由 C1 增加能力；不能在返回上限内的全量结果上做本地模块筛选冒充完整查询。
2. 所有来源分离 draftFilters 和 appliedFilters；服务端行、本地历史行、统计、分页、查询标签均对应同一次已执行查询。
3. 使用 B 的共享状态层接入首页、机组概览/监控、测点详情与告警管理；各页只渲染，不再各自推断告警状态。保留按来源的详情页签。
4. 首页显示活动数、待办数、来源覆盖/新鲜度；摘要跳转保留稳定事件身份和来源。不同来源延迟时标明各自更新时间，不虚构同一瞬时快照。
5. 事件详情提供“确认”“追加处置”“关闭”和审计时间线；按钮依据能力与权限启用，提交中防重入。只有服务端成功并回读后显示成功；冲突时提示刷新并保留未提交说明。
6. 活动状态与处理状态各一列；恢复但未处理仍能在待办找到。人工核验关闭显示依据，不将来源 unknown 渲染为 recovered。
7. 颜色使用共享严重程度规则。严重程度文字始终可见；用户自定义色只能改变呈现，不能降低严重级别、删除待办或更改优先级。

验收：同一事件在摘要、测点和详情中身份/状态一致；改筛选未查询时现有结果不变；全量入口不隐藏其他点位；事件可从发现追到关闭与审计。
