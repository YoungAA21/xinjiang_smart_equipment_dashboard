# 告警最小闭环：并行交付总计划

日期：2026-10-15。状态：计划已编制，尚未实施或联调。

## 如何同时推进

第一轮：A1 立即修复已确认的问题；S0 同时完成契约和业务确认；D 准备复现和基线。B/C 可以先搭结构和接口夹具，不自行决定未冻结的状态语义。

第二轮：S0 冻结后，A2、B1/B2、C1/C2/C3、D1/D2 同时进行。前后端通过同一份夹具推进，不必等整套后端完成才开始前端。

第三轮：B 提供状态层，A 接入页面，C 提供真实能力，D 按真实接口完成跨页、跨浏览器、断线和重启验收。通过后执行 C4/D3。

关键路径：S0 → 服务端稳定身份与持久化 → 可靠的源事件/活动快照 + 处理审计 → 前端真实接入 → 现场闭环验收。单独修好前端不能通过最终放行。

人员建议：2 名前端分别负责 A/B，1 名后端负责 C，1 名测试或负责人负责 D，现场负责人参加 S0/D3。人员不足时复用角色；不要让多个角色同时编辑同一个文件。C 是最可能的瓶颈，增加页面开发人员不能消除采集可靠性与后端接口依赖。

节奏建议：首个半天冻结 S0 并准备验收夹具；首日争取交付 A1 的独立修复。完整闭环工期需在核实后端、声纹接口和最短 DI 脉冲后估算，不能仅凭前端仓库承诺天数。

## S0：共同约定，所有计划必须使用

### 1. 来源和身份

- 来源固定为 collection / trend / acoustic / digital；集合中的事件键为 source + sourceEventId，两者都必须稳定。ID 全程用字符串，禁止转 Number。
- 一个异常从触发到恢复属于一次事件；恢复后再次触发生成新 sourceEventId。重复采样、重试、页面切换不生成新事件。
- 测点身份采用来源 + 后端稳定点位身份。采集来源保留 moduleId、pointId 及 channelId/pointCode；声纹使用 deviceId + channelId，并保留上游事件身份。
- 机组/测点无法唯一归属时显示“未归属”，进入待配置列表；模块级告警只归属模块，不将该模块每个测点标记为故障。
- 声纹与采集点位的关联需明确映射，禁止根据显示名称猜测。机组级统计按稳定机组身份去重。

### 2. 条件状态与处理状态分开

| 维度 | 值 | 含义 |
| --- | --- | --- |
| 记录性质 recordType | condition / occurrence | 持续异常 / 一次性事件 |
| 条件 conditionState | active / recovered / unknown / notApplicable | 是否仍异常；一次性事件可为 notApplicable |
| 处理 workflowState | unacknowledged / acknowledged / closed | 是否有人确认、是否完成关闭 |
| 来源 sourceHealth | healthy / stale / unavailable / incomplete | 能否信任当前来源结论 |

- 确认：只记录“谁在何时已知晓”，不修改条件状态，不消除活动报警。
- 处置：提交处理记录，可多次追加，不能覆盖历史。
- 自动恢复：只修改条件状态；恢复但未确认的事件仍在待办中。
- 关闭：需要确认、处置说明和解决依据。持续异常通常需后端已验证恢复；条件未知或上游无恢复能力时，必须走经批准的人工核验路径，记录核验人、时间、证据和原因，不能伪造 recovered。一次性事件确认并完成处置后可以关闭。
- 再次触发：生成新事件，旧事件及审计保持不变。正在异常且无人工核验依据时拒绝关闭。
- 声纹 status=0/1 的含义须由接口提供方确认；“已处理”不能直接映射 recovered。保留 rawStatus；接口含义未确认时条件状态为 unknown，并展示来源能力限制。

### 3. 来源能力与正常状态

- 每个来源报告支持的能力：活动快照、恢复事件、历史分页、确认/关闭写入、源时间与覆盖范围。
- 全局活动状态包含所有已启用的告警来源；未接入来源显式展示“未接入”，不得默认为无告警。
- 有可信活动事件则显示报警；已知活动事件与来源异常并存时同时展示两种信息。所有必需来源完整、足够新、成功返回且相关测点数据有效，才允许显示正常。
- 恢复条件由来源事件决定，失败、空页、超时、超过查询上限和缺数均不能代替恢复。
- 首页连接状态单独显示“采集连接正常/异常/待确认”；告警状态、待办数量、连接状态分别统计。
- 活动计数包含已确认但仍 active 的事件；待办计数包含未关闭事件。跨页数字明确范围、总数和查询时间。
- 建议初始轮询间隔：活动快照 5 秒、超过 15 秒未得到成功快照即标为 stale；最终由 S0 根据负载确认。陈旧计算同时检查服务端 generatedAt 和上游事件处理进度，不能只看浏览器收包时间。

### 4. 告警规则最少需要定什么

- 硬限值：明确上下边界是否包含等号、触发持续时长、恢复回差/持续时长、质量过滤、缺失/未来/乱序数据策略。记录规则版本、触发时阈值与单位，修改规则不能重写历史。
- 趋势：确认分析窗口、样本数量/覆盖率、变化率定义、触发与恢复规则、风险级别；前端统一展示后端结论。
- DI：六路分别登记“信号含义、工况事件/异常告警、启用状态、有效电平或边沿、最短有效脉冲、防抖、恢复规则、严重程度、启动为高电平时的行为”。当前仅四路有明确名称，其余两路含义需要现场确认。未确认前不自动将高电平解释为故障。
- 声纹：确认告警究竟是一次识别事件还是持续异常、是否有结束通知、事件与录音/样本类别的稳定关联。
- 记录点位当前值和历史触发值分别展示；单位标签变化不做数值换算，展示历史事件时保留事件发生时单位。

### 5. 接口最小契约（语义约定，路径待后端确定）

| 能力 | 必需输入/输出 | 约束 |
| --- | --- | --- |
| 活动快照 | generatedAt、snapshotVersion、完整活动列表或可遍历游标、准确 activeTotal、各来源 health/complete/lastProcessedAt | 单次 limit 截断不能冒充全量；总数与明细属于同一快照版本 |
| 历史与待办 | source/机组/模块/点位/时间/条件/处理状态筛选；total、稳定排序、分页或游标 | 模块筛选在服务端完成，不能对某页结果过滤后声称全模块 |
| 事件详情 | 稳定键、recordType、条件/处理状态、事件时间、触发/恢复值、阈值快照、单位、规则版本、revision、原始字段 | 当前实时值另取，不覆盖触发值；身份与映射缺失显式返回 |
| 确认 | 事件键、expectedRevision、idempotencyKey | 操作者由服务端身份确定；返回新 revision 和审计记录 |
| 追加处置 | 事件键、说明、解决依据/附件引用、expectedRevision、idempotencyKey | 持久化、追加式记录；允许尚未恢复时先记录处置 |
| 关闭 | 事件键、expectedRevision、idempotencyKey | 校验状态和解决依据；非法转换返回业务错误，并发冲突返回可识别的冲突结果 |
| 审计查询 | 事件键 | 可追溯触发、恢复、确认、处置、关闭、规则版本及人工核验 |

保持 5158 采集请求不携带 18080 声纹令牌。新增处理接口由后端明确其授权服务/网关与凭据，不直接将声纹令牌透传到采集服务。前端隐藏按钮不能代替服务端写权限校验。

### 6. 最小通知和交付范围

最小通知采用常驻活动告警数、待办数和可进入的事件列表；先保证有入口且不会因恢复丢失待办。现有自动弹窗暂停行为保持，待告警配置和通知策略明确后另行启用。

本期不要求工单系统、复杂派单、短信/邮件、声音、WebSocket、大屏重做或全量架构重写。数据大屏当前未注册路由，旧 dashboard store 有历史/示例告警代码；本期只避免新功能误用，不以它们作为当前闭环证据。

## 交付分级

- M1 前端纠偏：A1 + B1 的基本规范化及相应测试通过。可提前交付，但尚未形成可靠的处理闭环。
- M2 联调闭环：A2/B2 接入 C1/C2/C3，真实事件完成发现、确认、处置、恢复/核验、关闭、追溯。
- M3 现场放行：C4/D3 通过，浏览器关闭仍可靠记录、多人共享一致、来源中断不会假绿，回滚有演练证据。

只有 M3 可以宣称“最小告警闭环完成”。前端本地模拟、截图或打包成功均不能替代服务端与现场证据。

## 最终验收清单

- [ ] 四类来源与六路 DI 的定义、启用范围和能力表已签定。
- [ ] 每条来源事件有稳定键；无错归属、重复计数、录音串事件。
- [ ] 超过 1000 条历史时，早期未恢复事件仍出现在完整活动集合中。
- [ ] 缺数、断线、超时、旧/未来采样、处理进度滞后均不会被解释成恢复或正常。
- [ ] 浏览器关闭、刷新、切换账户、采集服务重启后，真实事件及处理审计仍可追溯。
- [ ] 操作员 A 确认，B 刷新后可见；两人并发修改不会丢记录。
- [ ] 确认不消除活动状态；恢复不自动消除待办；关闭受规则约束且有审计。
- [ ] 一次性声纹事件与缺少恢复能力的来源有经确认的处理路径，不会永久卡住或被假恢复。
- [ ] 首页、机组/点位、管理页使用同一口径，支持从摘要追到同一事件。
- [ ] 本地 DI 只有明确的历史归档身份，上线后不与后端事件双写双计。
- [ ] 自动测试、生产构建、两主题视觉及真实链路验收全部有记录；既有失败已判定并处理。
