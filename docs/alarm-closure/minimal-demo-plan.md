# 最小改动的告警闭环与演示计划

日期：2026-10-16。状态：计划，未实施。

本次按本文件执行。此前四条并行计划保留为后续正式建设参考，不作为本次交付前置条件。

## 一、目标和边界

复用现有“告警管理 → 采集报警 → 查看详情”，完成一条可重复演示的链路：

触发一条告警 → 在列表发现 → 确认 → 填写处置说明 → 信号恢复 → 关闭 → 刷新后查看处理记录。

只做一个前端演示闭环，不增加后端接口，不改采集协议、硬限值或趋势算法。本次仅扩展采集报警页；趋势、声纹继续保持现状。真实告警可附加本机处理记录，但后端原始事件及状态保持只读。

处理记录按当前账户保存在当前浏览器。界面注明“本机处理记录”；演示区和演示行标“演示数据”。这能验证交互闭环，不代表服务端留存、多人共享或浏览器关闭期间的真实采集闭环。

## 二、最少状态逻辑

保留两条互不替代的状态：

- 信号状态：当前告警 / 已恢复 / 未知。真实事件由原接口决定；演示事件由演示控制按钮决定。
- 处理状态：待确认 / 已确认 / 已关闭。单独保存，不修改真实事件的 status/isActive。

| 当前情况 | 允许操作 | 结果 |
| --- | --- | --- |
| 新事件 | 确认告警 | 保存确认人、确认时间；仍然显示当前告警 |
| 已确认 | 填写并保存处置说明 | 追加记录，信号状态不变 |
| 演示事件仍活动 | 模拟恢复 | 改为已恢复，处理状态不变 |
| 已确认 + 已恢复 + 有处置说明 | 关闭告警 | 保存关闭人、时间；历史和说明仍可查看 |
| 未确认、仍活动、未知或无说明 | 关闭不可用 | 展示具体缺少的条件 |
| 已恢复但未确认 | 确认、保存说明，再关闭 | 自动恢复不代表已经有人处理 |

重复确认/关闭不得重复追加记录。关闭后的旧事件保持只读；再次“触发演示告警”创建新的事件 ID。真实告警的恢复只能来自重新查询成功返回的同一事件，不能用事件从活动列表消失、超时或空结果代替。

真实事件在本次详情查询成功后才允许关闭；发生查询错误或最近成功读取超过 30 秒时，提示重新查询，关闭按钮禁用。保留旧记录供查看。该限制只是演示级保护，不提供服务端原子校验。

## 三、演示场景

采用一条明确的“温度超上限”采集报警，固定演示身份与后端数据隔离：

- 演示测点：演示温度点；单位 °C；上限 80。
- 初始值 70，触发值 85，恢复值 75。
- 控制区按钮：“触发演示告警”“模拟恢复”“重置演示”。不把控制按钮放在真实告警详情内。
- 每次触发生成 `demo:<唯一事件ID>`；完整记录始终带 source=demo。未恢复时再次触发不重复创建。
- 演示使用事件夹具呈现 85 > 80、75 < 80 的过程，不把这段前端逻辑作为真实告警判定器。

进入演示模式时，采集面板显示独立演示数据集和明确的演示标识，暂停该面板的真实查询/本地 DI 合并，不修改其筛选条件、服务器结果或缓存。演示不依赖模块元数据接口成功，可在登录后的现有应用中离线展示。

退出演示恢复原有真实列表与筛选快照，不修改真实告警；重新查询由现有查询按钮完成。演示记录刷新后继续保留；演示模式本身可默认退出，下次进入时继续查看。重置只清除当前账户的 demo 数据与其处理记录，不清空真实事件或其他 localStorage 配置。

## 五、最小数据保存规则

- 事件键为来源 + 原事件 ID。真实采集 ID 使用字符串；无稳定 ID 的真实事件仅允许查看，暂不提供处理按钮。
- 本机记录至少保存事件基本快照（身份、点位、触发时间、触发值、阈值、单位）、确认人/时间、说明记录、关闭人/时间及操作时间线。
- 演示记录额外保存当前信号值、活动/恢复状态及恢复时间；真实事件快照不作为后端当前状态的替代。
- 说明保存时去除首尾空白，空白不算处置依据；最少只要求一条非空说明，不增加附件、派单或工单字段。
- localStorage 按账户和版本命名；切换账户时同步重新加载，迟到响应不能写入新账户。账户不能识别时禁用持久处理操作并提示重新登录，不使用共享 default 键。
- 操作先完成存储再显示成功；存储失败不推进处理状态。缓存损坏时显示错误并禁用写入，避免静默覆盖旧记录，允许用户仅重置演示分区。
- 演示数据和真实本机处理记录使用不同的存储键，重置演示不会触碰真实记录。关闭记录留在列表和详情中，不因关闭删除事件。

## 六、三分钟演示脚本

1. 登录后进入“告警管理 → 采集报警”，开启演示模式。讲解：当前展示演示温度点，上限 80 °C，值 70 °C。
2. 点击“触发演示告警”。显示值 85、当前告警、待确认。打开详情，看到触发时间、触发值和上限。
3. 点击“确认告警”。处理状态变为已确认，当前告警仍保持；讲解“知晓不代表恢复”。
4. 填写“已检查散热风扇并清理进风口”，保存说明。此时仍活动，关闭按钮禁用并注明原因。
5. 点击演示控制区“模拟恢复”。值变为 75，信号状态变为已恢复；处理状态仍是已确认。
6. 点击“关闭告警”。显示已关闭及确认、处置、恢复、关闭时间线。
7. 刷新页面，重新进入演示模式，看到旧事件和处理记录；再次触发得到新事件，旧事件不被覆盖。
8. 点击“重置演示”可重演；退出演示返回真实列表，说明真实后端数据未被更改。

## 七、验收与实施节奏

- [ ] 活动事件确认后仍显示报警，不能关闭；缺说明不能关闭。
- [ ] 已恢复但未确认仍可见，确认、填说明后可关闭。
- [ ] 真实事件未知、查询失败或超过新鲜度窗口时不能本地判定恢复并关闭。
- [ ] 触发/恢复/关闭重复操作不重复生成事件或时间线；再触发创建新事件。
- [ ] 刷新保留本机记录；切账户不串记录；存储失败不提示成功。
- [ ] 演示可在元数据/后端不可用时运行，保持标识且不发新增写请求。
- [ ] 重置演示不影响真实记录；退出演示恢复原列表与筛选。
- [ ] 两主题完成三分钟脚本；现有回归与生产构建通过，既有失败单独核实处理。

建议一个前端顺序执行，避免为这点改动拆多人并行：先 store 与状态测试，再面板交互，再演示控制，最后视觉与全量验证。按上述固定范围，预计约 1–2 个工作日，实际取决于既有测试失败与页面联调情况。

本计划的完成标准是“单浏览器、当前账户、明确标识的演示闭环可重复运行”。正式服务端闭环仍参考旧总计划，不在本次演示工期内承诺。
